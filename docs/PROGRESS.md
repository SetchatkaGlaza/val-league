## Архив 5.3b
- Миграция не нужна (столбец `maps` добавлен в 5.3a; если 5.3a не применяли — `npm run db:migrate`).
- Сервер: `PUT /api/admin/matches/:id/result` принимает `maps` (`[{map, a, b, demoUrl}]`, 2–3 карты) для BO3; счёт серии считается сам (`validateMaps`, `seriesFromMaps` в `services/bracket.js`). Обычный счёт, итог серии и техпоражение очищают `maps`. Тесты: `npm test`, 14 из 14.
- Клиент: форма результата BO3 — «Сыгран, счёт по картам» (карта из пула турнира, очки, демо; третья карта появляется, если первые две разделились), «Только итог серии (2:0 или 2:1)», техпоражение, неявка. На странице матча карточка «Карты» с демо по каждой карте; в админке счёт по картам виден в строке матча.
- Адаптив: страница сетки (16 команд, длинные названия) и страница матча проверены на 360 и 390 px в headless Chromium, горизонтальной прокрутки у страницы нет, кнопки не меньше 36 px; правок вёрстки по итогам проверки не потребовалось, кроме формы результата.
- Не проверено: реальные сервер и БД, сборка Vite.
- Этап 5 завершён. Дальше: этап 6 (победители и публичные страницы).

## Архив 5.3a
- **Нужна миграция БД:** `npm run db:migrate` (три столбца в `matches`: `forfeit`, `forfeit_reason`, `maps`; `maps` пока не используется, его заполнит 5.3b).
- Сервер: `POST /api/admin/tournaments/:id/schedule` (массовое расписание), `PUT /api/admin/matches/:id/result` принимает `forfeit` и `demoUrl`; логика в `services/bracket.js` (`scheduleMatches`, `forfeitScore`). Тесты: `npm test`, 13 из 13.
- Клиент: в админке кнопка «Назначить время матчей», в форме результата выбор «Сыгран / Техническое поражение / Неявка», поле демо; подписи «Тех. поражение» / «Неявка» на сетке, странице матча и в «Мои матчи».
- Решения: при техпоражении и неявке победителю пишется счёт 13:0 (BO1) или 2:0 (BO3); обе команды не явились — не поддерживается (одна должна пройти дальше, выберите проигравшую по ситуации).
- Проверено: тесты сервера; админ-интерфейс в headless Chromium (390 px) на подставном API: расписание, ошибки полей, неявка, обычный счёт, исправление. SQL новых запросов на реальной БД не запускался.

## Состояние на архив 5.2
- Клиент (новое): `views/bracket.js` (`/tournaments/<slug>/bracket`), `views/match.js` (`/matches/<id>`), `views/bracket-parts.js` (общая отрисовка сетки), `views/admin-bracket.js` (раздел «Сетка и матчи» в админке), `styles/bracket.css`. Правки: `routes.js`, `js/api.js` (`bracket`, `matches`, методы админки), `views/admin-tournament.js` (раздел подключён, панель статуса обновляется после финала, сетка перечитывается после изменений заявок), `views/account.js` («Мои матчи»), `views/tournament.js` (кнопка сетки), `views/tournament-parts.js` (тексты ошибок сетки).
- Сервер: единственная правка — поле `hasBracket` в `serialize` и `EXISTS(...)` в `TSELECT` (`controllers/tournaments.js`). Его SQL подтвердит `npm run smoke`.
- Проверено: серверные тесты (`npm test`, 11 из 11); экраны сетки (6 и 16 команд, проходы без игры), админка (формирование, ручной посев, ввод счёта, ошибка ничьей, продвижение победителя), страница матча (лобби участнику, сыгранный матч, путь команд) и загрузка всех изменённых модулей прогнаны в headless Chromium на подставном API; на телефоне (390 px) страница не расползается. Сборка Vite в среде разработки не запускалась (нет сети), реальный сервер и БД тоже.
- Открытые решения для владельца: сетка скрыта у черновиков; автообновление сетки 30 с, матча 20 с; «Мои матчи» показывают до 8 записей.
- Убрано из архива (снова вернулись при заливке): файл `h --force-with-lease origin main` и `client/src/data/demo.js`.
- Следующее (5.3): массовое расписание (старт первого раунда + интервал), техническое поражение и неявка, счёт по картам BO3, ссылки на демо при вводе результата, доводка адаптива.
