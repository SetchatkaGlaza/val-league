## Архив 9.2 (Steam: регистрация, ник, отвязка, REQUIRE_STEAM)
- Миграция БД **не нужна** (`users.email`, `password_hash` уже допускали NULL, `steam_id` уникален). Сервер **перезапустить**. Новых пакетов и настроек `.env` нет. Файл архива: `val-league-9.2.zip`.
- Как это работает для игрока: «Войти через Steam» (или «Продолжить через Steam» на регистрации) → если аккаунта с таким Steam нет, сайт открывает `/steam-signup` с именем профиля Steam, предложенным ником (если имя подходит) и галочкой согласия → «Создать аккаунт» → игрок сразу вошёл. Почты и пароля у такого аккаунта нет. В кабинете у аккаунта с почтой и паролем рядом со Steam кнопка «Отвязать»: нужно ввести пароль.
- Сервер: `services/steam.js` (+`signSignup`/`readSignup`: подписанная cookie `val_steam_new`, 15 минут, отдельная «аудитория», путь `/api/auth/steam`; `canUnlinkSteam`), `controllers/steam.js` (ветка «нет аккаунта» вместо ошибки `steam_new` ставит cookie и ведёт на `/steam-signup`; `GET /api/auth/steam/pending` — имя Steam; `POST /api/auth/steam/register {nick, terms}` — создаёт пользователя), `controllers/account.js` + `routes/account.js` (`POST /api/account/steam/unlink {password}`), `routes/auth.js`, `controllers/auth.js` (`publicUser` + `emailVerified`, `hasPassword` для клиента).
- Безопасность: Steam ID берётся только из cookie, выданной после `check_authentication` у Steam (из тела запроса игнорируется, есть тест); cookie выдаётся только при обычном входе (при привязке нет), гасится после регистрации, токены сессии и состояния входа для неё не подходят; регистрация только создаёт новую запись, существующие аккаунты и привязки не трогает (уникальность Steam ID и ника проверяет БД: `nick_taken`, `steam_exists`); у заблокированного аккаунта по-прежнему вход невозможен; почтовый вход не менялся. Отвязка: нужен пароль (лимит как при смене пароля), подтверждённая почта и пароль (иначе `last_login_method`), при `REQUIRE_STEAM=true` нельзя, пока игрок в активной заявке на предстоящий или идущий турнир (`in_tournament`).
- Исправлено по пути: игрок со Steam, но без подтверждённой почты, считался «неподтверждённым» при подаче заявки на турнир (`roster_unverified`). Теперь подтверждённым считается и тот, у кого привязан Steam (`services/registrations.js`, `controllers/registrations.js`); блокировка по-прежнему исключает.
- Клиент: `views/steam-signup.js` (новая страница), правки `routes.js`, `js/api.js` (`auth.steamPending/steamRegister`, `account.steamUnlink` + демо-ответы), `views/login.js` (тексты `steam_expired`, `steam_exists`), `views/account.js` (отвязка, подсказка «Единственный способ входа»), `styles/auth.css`.
- `REQUIRE_STEAM` **не включён** (по умолчанию выключен): включать сознательно, порядок в `docs/AUTH.md`. Сейчас у существующих игроков с почтой Steam не привязан, после включения они не смогут подать заявку, пока не привяжут его.
- Проверено: `node --test` в `server` — 133 из 133 (21 новый в `test/steam-signup.test.js`: подпись и срок cookie, чужие токены, регистрация, игнорирование Steam ID из тела, проверка ника и согласия, занятый ник, повтор и уже существующий Steam, возврат со Steam (новый игрок, не подтверждено, режим привязки, заблокированный), отвязка (пароль, нет почты, неподтверждённая почта, `REQUIRE_STEAM` и активная заявка), состав заявки). Контроллеры прогнаны на подставной базе (подменён `pool.query`) и подставном ответе Steam. Клиент в headless Chromium на 360, 390 и 1280 px, на тестовом стенде без Vite с подставным API: 105 проверок из 105 (нет cookie → вход с сообщением; форма ника; ошибки поля; занятый ник; сбой сервера; Steam уже зарегистрирован; успех и профиль без почты; повтор после регистрации; экранирование имени Steam; отвязка с неверным паролем, с активной заявкой, успешная; длинное имя Steam; кнопки не ниже 32 px; нет горизонтальной прокрутки; нет ошибок консоли).
- **Не проверено:** реальный переход на steamcommunity.com (нет сети: запрос подтверждения проверен только на подставном ответе); реальные PostgreSQL и Express (SQL `INSERT INTO users … RETURNING *`, `UPDATE users SET steam_id = NULL … FOR UPDATE`, имена ограничений `users_steam_id_key` / `users_nick_key`, по которым код различает `steam_exists` и `nick_taken`; в стандартной схеме Postgres они именно такие, но на живой базе не проверялось); сборка Vite; внешний вид на реальных шрифтах (на `/login` при 360 px сохраняется 1 px запаса по ширине, он был и до 9.2, см. 9.1).
- Исправление после первого показа: на `/steam-signup` поле ника, галочка и кнопка были невидимы при включённой анимации (класс `reveal-field` скрывает элементы до скрипта, а форма вставляется позже). Класс убран; проверено в Chromium с анимацией (`.motion`) на 390 px. Раньше проверки шли с отключённой анимацией и это пропустили.
- Известные ограничения: у аккаунта, созданного через Steam, нет почты и пароля, поэтому он не может отвязать Steam, а при потере Steam войти нельзя (обратиться к организаторам); добавление почты и пароля — необязательный этап 9.3. Отвязанный Steam можно сразу привязать к другому аккаунту (проверка уникальности есть, ограничения «раз в N дней» нет). Игрок, удаливший аккаунт, может зарегистрироваться заново (как и по почте).
- Следующий этап: **10 — подготовка к выкладке** (сборка, окружение, HTTPS, бэкапы; см. `docs/ROADMAP.md`). Telegram-бот ведётся отдельным треком (`docs/telegram`).
