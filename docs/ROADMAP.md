## Этап 4. Регистрация команды на турнир и оплата — ✅ готово
Описание, правила и API: `docs/REGISTRATION.md`. Остались хвосты, которые закрываются позже: уведомления (этап 9), общий список заявок с фильтрами и журнал действий (этап 8), проверка Steam у игроков (включается `REQUIRE_STEAM=true` после этапа 9).

## Этап 5. Сетка, расписание, страница матча
БД: `matches` (`tournament_id, round, position, team_a, team_b, score_a, score_b, winner_id, status, starts_at, next_match_id, lobby_info`).
Логика: генерация Single Elimination при переходе турнира в `live` — посев (случайный или по рейтингу позже), «bye» для неполных сеток (число команд не степень двойки), связи «победитель идёт в матч N». Ввод результата админом пересчитывает следующий матч; исправление результата допускается, пока следующий матч не сыгран.
API/UI: `GET /tournaments/:slug/bracket`, `GET /matches/:id`, `PATCH /admin/matches/:id`; страница `/tournaments/:slug/bracket` (горизонтальный скролл на телефоне, масштабирование), `/matches/:id` (команды, счёт, время, данные лобби, ссылка на демо). Завершение финала автоматически завершает турнир и заполняет `winner_*` (сейчас вручную). Сетка строится из оплаченных заявок (`status = 'paid'`); при старте турнира неоплаченные заявки уже снимаются автоматически (этап 4).

## Этап 6. Победители и публичные страницы
Архив победителей `/winners` (из завершённых турниров), новости (`news`: заголовок, текст, обложка, дата, черновик/публикация), «О лиге и FAQ», «Рекламодателям» (форма заявки → письмо/таблица `ad_requests`), контакты; блок новостей на главной; `sitemap.xml`, OG-теги для страниц турниров.

## Этап 7. Рейтинг и профиль игрока
Очки за места и участие (таблица `rating_events`), рейтинг игроков и команд `/rating`, публичный профиль `/players/<ник>` (команды, турниры, матчи, места). Ники в составах и сетках становятся ссылками. Решить: ограничение смены ника (раз в N дней) — чтобы история не путалась.

## Этап 8. Остальная админка
Общий список заявок и оплат по всем турнирам с фильтрами (базовое подтверждение/снятие уже есть в карточке турнира), журнал действий `audit_log`, пользователи (поиск, блокировка, роли, сброс подтверждения почты), команды (расформирование), новости, реклама и партнёры (логотипы на главной вместо плашек), редактирование результатов матчей, экспорт заявок в CSV.

## Этап 9. Steam и Telegram
Вход/привязка через Steam OpenID (замена заглушки `/api/auth/steam`, `passport-steam` уже в зависимостях), запрет регистрации на турнир без подтверждённого Steam, защита от привязки одного Steam к двум аккаунтам.
Бот Telegram: привязка кодом (`user_tokens.kind = 'telegram_link'` и маршруты `/api/account/telegram/*` уже подготовлены), webhook. Очередь уведомлений `notifications_outbox` + воркер: «регистрация подтверждена», «турнир завтра», «матч через 30 минут», приглашения в команды (почта + Telegram) — в соответствии с настройками из `/settings`.

## Этап 10. Выкладка
VPS или PaaS в РФ; домен и DNS; nginx (SPA + прокси `/api`, пример в README); HTTPS (Let’s Encrypt, автопродление); процесс-менеджер (systemd или pm2) с автозапуском; `NODE_ENV=production`, `TRUST_PROXY=1`, свой `JWT_SECRET`, `CLIENT_URL` с https; SMTP (Яндекс 360 / Unisender) с SPF/DKIM/DMARC; ежедневный `pg_dump` + копия `UPLOADS_DIR` во внешнее хранилище с проверкой восстановления; мониторинг (UptimeRobot) и логи с ротацией; политика/регламент с реальными реквизитами (`client/src/config.js`); проверка заголовков безопасности (CSP для клиента через nginx).

## Сквозные задачи (делать по ходу)
- **Автотесты.** Расширять `npm run smoke` под каждый этап; в перспективе — vitest + supertest на отдельной тестовой БД.
- **Миграции.** Пока схема идемпотентна (`CREATE … IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`). Когда понадобится менять/удалять столбцы — перейти на `node-pg-migrate`.
- **Правила, которые надо зафиксировать с заказчиком:** срок оплаты заявки, размер листа ожидания, политика возврата взноса, ограничение смены ника, посев сетки.
- **Безопасность:** лимиты на новые POST-маршруты, журнал админ-действий (этап 8), проверка загрузок (уже по сигнатуре файла), регулярное обновление зависимостей (`npm audit`).
