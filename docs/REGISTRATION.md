# Регистрация команды на турнир и оплата (этап 4)

## Как это работает для игроков
1. Капитан открывает страницу турнира → блок «Участие» → «Зарегистрировать команду».
2. Выбирает ровно N игроков заявки (5 для 5×5, 2 для 2×2) из состава команды и ставит галочку «принимаю регламент».
   Недоступных игроков видно сразу, с причиной: почта не подтверждена, уже в другой заявке на этот турнир, нет Steam (когда включено).
3. Если места есть:
   - турнир платный → заявка получает статус **«Ждёт оплаты»**, показываются сумма, **код платежа** (`VAL-XXXXXX`), срок и реквизиты;
   - турнир бесплатный → сразу **«Участие подтверждено»**.
   Если мест нет — **«Лист ожидания»** с номером в очереди.
4. Капитан переводит взнос, указав код в комментарии. Администратор подтверждает оплату вручную → **«Участие подтверждено»**.
5. До закрытия регистрации капитан может **изменить состав заявки** или **отменить** её. Оплаченную заявку тоже можно отменить, но взнос возвращают вручную (заявка получает пометку «нужен возврат»).
6. Остальные игроки состава видят заявку (статус и состав) в кабинете, в блоке «Мои турниры», и на странице турнира.

## Правила (допущения по умолчанию — согласуйте с организаторами)
Значения лежат в `server/src/config.js` → `registration` и меняются в одном месте.
| Правило | Сейчас | Где |
| --- | --- | --- |
| Регистрация, отмена и смена состава закрываются за | 60 минут до старта | `closeMinutes` |
| Сколько держим место за неоплаченной заявкой | 24 часа, но не позже закрытия регистрации | `payHours` |
| Размер листа ожидания | 8 команд | `waitlistMax` |
| Лист ожидания движется | автоматически при освобождении места, пока регистрация не закрыта | `promoteWaitlist` |
| Возврат взноса | вручную: оплаченную заявку сняли → «нужен возврат» → админ отмечает «Взнос возвращён» | админка |
| Требовать Steam у игроков | выключено; включается `REQUIRE_STEAM=true` (порядок — в `docs/AUTH.md`, этап 9.2) | `requireSteam` |
| Текст «Как оплатить» | переменная `PAYMENT_DETAILS` в `server/.env` | `paymentDetails` |

Пример для `server/.env`: `PAYMENT_DETAILS=Перевод по СБП на +7 900 000-00-00 (Иван И.). В комментарии укажите код платежа.`
(Нужен перезапуск сервера.)

## Заморозка состава
Пока у команды есть живая заявка (ждёт оплаты / оплачена / лист ожидания) на предстоящий или идущий турнир:
- заявленного игрока нельзя исключить и он не может уйти из команды (`409 roster_locked`): капитан сначала меняет состав заявки;
- команду нельзя удалить (`409 team_registered`);
- аккаунт игрока из заявки нельзя удалить (`409 in_tournament`).
Состав самой заявки — снимок игроков на момент подачи; он меняется только через «Изменить состав» и только до закрытия регистрации.
Игрок не может быть в двух живых заявках одного турнира (`409 player_busy`), команда — подать вторую заявку (`409 already_registered`).

## Связь с сеткой
Сетка строится из оплаченных заявок. Пока турнир в статусе «анонс», любое изменение набора оплаченных команд (подтверждение, снятие, отказ, бесплатная регистрация) удаляет готовую сетку: её нужно сформировать заново (`docs/BRACKET.md`). В идущем турнире оплаченную заявку админ снять не может (`tournament_live`).

## Автоматика
- Раз в 5 минут сервер снимает заявки с истёкшим сроком оплаты (причина «не оплачена вовремя») и двигает лист ожидания.
  Если перевод всё же пришёл позже, админ нажимает «Оплата пришла»: заявка возвращается, если место ещё свободно.
- Старт турнира («Начать турнир»): неоплаченные заявки и лист ожидания снимаются.
- Отмена турнира: все живые заявки снимаются, оплаченные помечаются «нужен возврат».
- Увеличение лимита команд в админке сразу пускает людей из листа ожидания.

## Ограничения админки (защита от ошибок)
- нельзя уменьшить лимит ниже числа занятых мест (`max_below_occupied`) и изменить формат состава при наличии заявок (`has_registrations`);
- нельзя вернуть турнир в черновик, пока есть заявки;
- турнир с оплаченными заявками или невозвращёнными взносами не удаляется (`has_payments`): сначала отметьте возврат.

## API
Игрок (нужен вход):
| Метод | Путь | Тело / ответ |
| --- | --- | --- |
| GET | `/api/tournaments/:slug/registration` | `{ canRegister, closesAt, requireSteam, holdHours, waitlistMax, teams: [{ slug, name, members: [{ id, nick, role, verified, steam, busy }], registration }], asPlayer }` |
| POST | `/api/tournaments/:slug/registrations` | `{ teamSlug, roster: [userId…], acceptRules: true }` → `201 { registration }` |
| GET | `/api/registrations/mine` | заявки игрока и его команд |
| GET | `/api/registrations/:id` | капитан, игрок состава или админ |
| POST | `/api/registrations/:id/cancel` | капитан |
| PUT | `/api/registrations/:id/roster` | `{ roster }`, капитан, до закрытия |

Ошибки подачи: `registration_closed, already_registered, player_busy / roster_unverified / roster_no_steam (+details: ники), not_member, tournament_full, validation (field: roster | acceptRules)`.

Админ (`/api/admin`):
| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/tournaments/:id/registrations` | все заявки турнира, срочные сверху |
| POST | `/registrations/:id/confirm` | подтвердить оплату (в том числе вернуть просроченную) |
| POST | `/registrations/:id/cancel` | снять заявку `{ note? }` |
| POST | `/registrations/:id/refunded` | отметить возврат взноса |

## База данных
Таблица `tournament_registrations` (см. `server/src/db/schema.sql`): статус, снимок состава (`roster`, `roster_ids`), сумма на момент заявки, код платежа, срок оплаты, причина снятия, флаг `refund_due`.
Одна живая заявка на команду и турнир обеспечена частичным уникальным индексом. История заявок остаётся, даже если команду удалили (`team_id` обнуляется, имя сохранено).
