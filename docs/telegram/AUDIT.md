# Аудит VAL перед интеграцией Telegram-бота (этап 1)

Дата: 2026-10-16. Основа: исходники `val-league.zip` (ветка `main`, последний коммит `76ec00e` «Регистрация команды на турнир и оплата»).
Метод: чтение кода. БД PostgreSQL и сеть в среде аудита недоступны, поэтому **ничего из сайта не запускалось**; зависимостей `telegraf`, `supertest` и т. п. в `node_modules` нет.

## 1. Стек (подтверждён кодом)
npm workspaces `client` + `server`; клиент — Vite + нативный JS SPA; сервер — Node ≥20, Express 4, ES modules, `pg`, zod, helmet, cors, cookie-parser, express-rate-limit, jsonwebtoken (cookie `val_session`), bcryptjs, nodemailer. Миграции — единый идемпотентный `server/src/db/schema.sql` (`npm run db:migrate`), отдельной системы миграций нет. Тестов и линтера нет; есть `npm run smoke` (сквозной скрипт `server/scripts/smoke.mjs`, нужен живой сервер и БД) и prettier.

## 4. Расхождения между стартовым архивом и сайтом
1. **Формат привязки.** Клиент уже умеет только код: «отправьте боту `/start <код>`» и кнопку проверки. Стартер ожидает deep link `?start=link_<token>`. Решение: один токен, два способа (кнопка со ссылкой + ручной ввод кода), см. ARCHITECTURE.md.
2. **Длина токена.** `randomToken()` сайта — 64 hex-символа. Payload `/start` у Telegram ограничен **64 символами** (`A-Za-z0-9_-`), а с префиксом `link_` стартер дал бы 69 — ссылка не работала бы. Нужен отдельный токен ≤ 59 символов (план: base64url от 24 байт = 32 символа).
3. **Эндпоинты.** Стартер вызывает `/api/integrations/telegram/confirm-link`, на сайте его нет; сайт уже зарезервировал `/api/account/telegram/*`. Новый внутренний маршрут нужен, пользовательские — реализуются на месте заглушек.
4. **Список событий стартера** включает `match.*` и `admin.system_alert` — этих событий на сайте нет; в рабочий allowlist они не попадут.
5. **Настройки уведомлений** не содержат ключа для приглашений в команду. Нужен новый ключ `invites` с обратной совместимостью (старые записи без него).
6. **Дедупликация** в стартере — в памяти, после отправки; для production заменяется outbox.

## 5. Найденные дефекты сайта, влияющие на интеграцию
- **`publicUser` (`auth.js:44`)**: `telegram` строится из `telegram_username`. Пользователь Telegram **без username** окажется «не привязанным» в UI, хотя `telegram_id` есть. Надо ориентироваться на `telegram_id`.
- `telegram_username` в БД есть, но Telegram username меняется и не является идентификатором: использовать только для показа.
- Глобальный лимит `/api` (120/мин на IP) применяется и к бот-вызовам — для сервера бота с одного IP нужен отдельный лимит/исключение.
- `sameOrigin` пропускает запросы без заголовка `Origin`, поэтому защита CSRF не мешает боту, но и не защищает внутренние маршруты: их защищает только сервисная аутентификация (HMAC).
- В архиве `val-league.zip` лежали `server/.env` и `client/.env` (они в `.gitignore`, реальных секретов в них нет — `JWT_SECRET` пуст, пароль БД девелоперский). В архивы этапов они не включаются.
- `deleteAccount` каскадно удаляет пользователя — привязка Telegram исчезает вместе с ним (хорошо), но очередь outbox должна переживать удаление (`user_id` с `ON DELETE CASCADE` для неотправленных сообщений).
