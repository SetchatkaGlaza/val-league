# Журнал работ над Telegram-ботом VAL

Файл для продолжения работы в новых сессиях: читать первым. Рабочая ветка: `feature/telegram-bot`.

## Этапы
| # | Этап | Статус |
|---|---|---|
| 1 | Аудит, архитектура, импорт стартера в `bot/` | **готов** (этот архив) |
| 2 | Привязка: миграция, `/api/account/telegram/*`, `/api/integrations/telegram/confirm-link`, HMAC, тесты | не начат |
| 3 | Outbox + воркер + хуки в событиях сайта | не начат |
| 4 | Бот: форматирование по allowlist, `/settings`, `/unlink`, 429/retry, healthcheck, shutdown | не начат |
| 5 | Клиент: ссылка привязки, ключ `invites`, исправление признака привязки | не начат |
| 6 | Тесты, отчёт по безопасности, инструкции Windows/Linux, деплой | не начат |

## Этап 1 — итог
- Изучено: весь `server/`, `schema.sql`, `docs/`, клиентские `account.js`/`settings.js`/`api.js`, стартовый бот целиком.
- Файлы: `docs/telegram/AUDIT.md`, `ARCHITECTURE.md`, `PROGRESS.md`, `docs/telegram/starter/*` (исходные доки стартера), `bot/*` (стартер без изменений кода + `assets/*.svg`).
- Миграций нет. Код сайта не менялся.
- Запускалось: `node --check` по файлам бота (ок). Не запускалось: тесты, сборка, `npm install`, БД, Telegram.
- Открытые вопросы к владельцу: (1) username бота (`@…`) и домен сайта; (2) где будет хоститься бот и есть ли публичный HTTPS для webhook; (3) уведомлять ли весь состав или только капитана о статусах заявки (по умолчанию: капитан + состав paid-заявки).
- Следующий этап: 2 (привязка).

## Окружение сессий
Песочница без сети и без PostgreSQL: `npm install` новых пакетов невозможен. Тесты этапов 2–3 пишутся на `node:test` с подменой БД; интеграционные проверки с реальной БД будут отдельными скриптами, которые запускаются у владельца.
