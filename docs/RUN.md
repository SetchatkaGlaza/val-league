# Запуск и обновление

Для Windows, macOS и Linux. Нужны: **Node.js 20+** (проверка: `node -v`), **PostgreSQL 14+** (pgAdmin или Docker), git.

## A. Обновление существующей установки (вы уже запускали сайт)
1. Остановите `npm run dev` (Ctrl+C).
2. Замените папку проекта содержимым архива (как обычно: удалить старую → распаковать новую).
   В архив включены ваши `server/.env`, `client/.env`, `server/uploads` (логотипы) и `.git`, поэтому настройки и данные сохранятся.
   Если вы распаковали **без** `node_modules`, выполните `npm install` (новых пакетов в этой версии нет).
3. Примените схему БД — добавятся таблица `tournaments` и два столбца в `users` (повторный запуск безопасен):
   ```bash
   npm run db:migrate
   ```
   Должно появиться «Схема БД применена».
4. Запустите: `npm run dev` → сайт на http://localhost:5173, API на http://localhost:4000.
5. Сделайте себя администратором (один раз):
   ```bash
   npm run admin:make -- ваша_почта@example.com
   ```
   (можно указать ник вместо почты). Обновите страницу сайта — в шапке появится «Админка».
   Модератор (заявки и результаты матчей без остальных прав): добавьте `--moderator`; снять права: `--remove`.
6. (Для этапа 4) Укажите в `server/.env` текст оплаты, который увидят капитаны, и перезапустите сервер:
   `PAYMENT_DETAILS=Перевод по СБП на +7 900 000-00-00 (Иван И.). В комментарии укажите код платежа.`
   Без этой строки показывается заглушка «Реквизиты пришлёт организатор…».
7. Проверьте работу: `npm run smoke` (при запущенном сервере) — см. раздел «Автопроверка».

## B. Первый запуск с нуля
```bash
git clone <ваш репозиторий> val-league && cd val-league
cp server/.env.example server/.env      # Windows PowerShell: Copy-Item server/.env.example server/.env
cp client/.env.example client/.env
```
1. **База данных.** Вариант с Docker: `npm run db:up`. Вариант с pgAdmin — шаги в `docs/DATABASE.md`.
2. **JWT_SECRET** в `server/.env` (минимум 32 символа). Сгенерировать:
   `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`
3. `npm install` → `npm run db:migrate` → `npm run dev`.
4. Откройте http://localhost:4000/api/health — должно быть `{"ok":true,"db":true}`.
5. Зарегистрируйтесь на сайте. Пока `SMTP_HOST` пуст, письмо с подтверждением **печатается в консоли сервера** (`[ПИСЬМО → …]`): скопируйте ссылку в браузер.
6. `npm run admin:make -- ваша_почта@example.com`, перезагрузите страницу.

## Что проверить руками (5 минут)
| Что | Как |
| --- | --- |
| Турнир | «Админка» → «Создать турнир» → заполните → «Создать черновик» → «Опубликовать» |
| Публичные страницы | «Турниры» (вкладки), страница турнира, главная (блок «Ближайший турнир») |
| Завершение | «Начать турнир» → «Завершить турнир» с победителем → блок «Последние победители» на главной |
| Заявка на турнир | войдите капитаном команды с нужным числом игроков (для 2×2 — двое) → страница опубликованного турнира → «Зарегистрировать команду» → выберите состав → получите код платежа; в «Админке» турнира нажмите «Подтвердить оплату»; под вторым аккаунтом проверьте лист ожидания |
| Команды | «Команды» (каталог, поиск), создание, приглашение по нику и ссылке |
| Аккаунт | «Настройки»: ник, пароль (после смены остальные сессии выходят), уведомления, удаление |
| Телефон | откройте DevTools → режим устройства (360 px): меню-бургер, таблица админки карточками, формы |

## Юнит-тесты (`npm test`)
Проверяют чистую логику сетки (посев, проходы без игры, связи матчей, названия раундов, счёт). База данных не нужна, выполняются за секунду.

## Автопроверка (`npm run smoke`)
**Перед запуском** добавьте в `server/.env` две строки и перезапустите сервер (иначе сработают лимиты запросов, их цель — защита сайта):
```
WRITE_LIMIT=1000
API_LIMIT=1000
```
После проверки строки можно удалить.
Сквозной сценарий по API: регистрация четырёх тестовых игроков, заявки на турнир (оплата, лист ожидания, заморозка состава, возврат), сетка и матчи (формирование, лобби, результаты, автозавершение турнира), смена ника и пароля, команда, приглашение, передача капитанства,
запрет удаления капитана, права админа, весь жизненный цикл турнира, победители, удаление аккаунта.
Тестовые данные (`smk_*`, «Smoke …», «Smk2 …») удаляются автоматически. Нужен запущенный сервер (`npm run dev:server`) и применённая схема.
Лимиты запросов (регистрация — 40 за 15 минут с одного IP) позволяют запускать скрипт много раз подряд.

## Частые проблемы
| Симптом | Решение |
| --- | --- |
| `relation "tournaments" / "tournament_registrations" does not exist` | не выполнили `npm run db:migrate` |
| Заявки не снимаются по сроку | сервер должен быть запущен: проверка идёт раз в 5 минут внутри него |
| В шапке нет «Админка» | `admin:make` не нашёл пользователя (регистрация и подтверждение почты обязательны) или нужно перезагрузить страницу |
| «Нет доступа» в админке | роль в БД не `admin`: проверьте `SELECT nick, role FROM users;` |
| Белый экран после обновления | остановите и снова запустите `npm run dev` (Vite кэширует), Ctrl+F5 в браузере |
| 403 на POST-запросах | `CLIENT_URL` в `server/.env` не совпадает с адресом, с которого открыт сайт (по умолчанию `http://localhost:5173`) |
| Порт занят | поменяйте `PORT` в `server/.env` и `target` прокси в `client/vite.config.js` |

## Сборка и продакшен (кратко; подробно — этап 10 в `docs/ROADMAP.md`)
```bash
npm run build                                   # клиент → client/dist
NODE_ENV=production node server/src/index.js    # API (нужны JWT_SECRET, CLIENT_URL, DATABASE_URL, TRUST_PROXY=1 за nginx)
```
Пример nginx — в `README.md`. Логотипы лежат в `UPLOADS_DIR` (по умолчанию `server/uploads`): включайте их в бэкапы вместе с БД.

## Тестовые данные (`npm run db:seed`)
Создаёт 12 команд (по 5 основных игроков, у 5 команд есть 1–2 запасных), у всех подтверждена почта, пароль `Password1`.
Турнир «VAL Test Cup» (`/tournaments/val-test-cup`, 5×5, BO1): 10 оплаченных заявок, 1 ждёт оплаты, 1 команда без заявки.
Вход капитаном: `severnyy-veter-1@seed.val.test` (адрес у остальных: `<адрес-команды>-1@seed.val.test`).
Нужны применённая схема (`npm run db:migrate`) и `DATABASE_URL` в `server/.env`; сервер запускать не обязательно.
Повторный запуск заново создаёт тестовые данные; убрать всё тестовое: `npm run db:seed -- --remove`.
