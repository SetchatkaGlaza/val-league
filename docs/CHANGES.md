# Что изменено в этой версии (проверка + этапы 2–3)

## Результаты проверки этапа 1 (команды)
Серверная часть (транзакции с блокировкой строки команды, лимиты состава, приглашения по нику и ссылке, логотипы с проверкой по сигнатуре файла) и страницы команды/создания/приглашения — в порядке, переделки не потребовали. Найденные пробелы закрыты:
| Находка | Исправление |
| --- | --- |
| Клиент вызывал `/api/account/*`, на сервере маршрутов не было: ник, пароль, уведомления, удаление аккаунта не работали | Добавлены `POST /account/profile, /password, /notifications, /delete` |
| Удаление капитана оставляло команду без капитана (`captain_id = NULL`) | Капитан команды с другими игроками обязан сначала передать капитанство (`409 captain_must_transfer` + названия команд, UI показывает их); команды, где он один, удаляются; последнего админа удалить нельзя |
| После смены/сброса пароля старые сессии оставались действующими (JWT) | Столбец `users.password_changed_at`: более ранние сессии перестают работать, текущая получает новую cookie |
| Подбор текущего пароля через «Сменить пароль» не ограничивался | Лимит 10 неудачных попыток за 15 минут на пользователя |
| Кнопки Telegram в кабинете отвечали «Не удалось выполнить»; возврат после Steam ничего не показывал | Сервер отвечает `501 soon`, клиент объясняет, что функция появится позже; на `/account?error=steam_soon` показывается пояснение |
| Шапка: нет ссылок на турниры/команды, на телефоне пункты теснились | Новая шапка с бургер-меню (≤760 px), доступная с клавиатуры (Esc, aria-expanded) |
| Нет каталога команд | Страница `/teams` с поиском и «Показать ещё» |
| Текст в «Настройках» про «капитан останется без капитана» устарел | Обновлён |

## Этап 2. Админка турниров
Админ-API и страницы `/admin`, `/admin/tournaments/new`, `/admin/tournaments/<id>`; роль выдаётся командой `npm run admin:make -- почта`. Подробности — `docs/TOURNAMENTS.md`.

## Этап 3. Список и страница турнира, главная из БД
`/tournaments` (вкладки со счётчиками), `/tournaments/<slug>`, главная берёт ближайший турнир и победителей из БД (демо-данные `client/src/data/demo.js` удалены). Для страницы турнира готовы: таймер, призовые по местам, пул карт, формат, описание, победитель, список команд (пока пустой), состояния «загрузка / не найдено / ошибка».

## Дополнительно
- `npm run smoke` — сквозная автопроверка API (≈50 проверок), `docs/RUN.md` — подробный запуск и обновление.
- Лимит JSON поднят с 10 до 32 КБ (описание турнира до 3000 символов).
- Ошибки API могут нести `details` (используется при удалении капитана).

## Ограничения проверки
В среде разработки не было PostgreSQL и сборки Vite: код проверен статически (синтаксис всех файлов, согласованность импортов/экспортов, запуск сервера, ответы маршрутов без БД, прогон чистых функций). SQL и сквозные сценарии подтверждаются на вашей машине командой `npm run smoke`.

# Версия 2: этап 4 (регистрация на турнир и оплата)
- **Заявки команд.** Капитан выбирает состав, принимает регламент, получает код платежа и реквизиты; админ подтверждает оплату; лист ожидания, автоматическое снятие неоплаченных заявок, возврат взноса вручную. `docs/REGISTRATION.md`.
- **Правило смены состава** (было отложено): регистрация, отмена и смена состава закрываются за 60 минут до старта; пока заявка живая, заявленного игрока нельзя исключить, команду и аккаунт игрока удалить нельзя.
- **Админка.** Блок «Заявки команд» в карточке турнира (подтвердить, снять, вернуть), счётчики «ждут подтверждения оплаты» и «взносов к возврату» на сводке; защита от опасных правок (лимит ниже занятых мест, смена формата при наличии заявок, удаление турнира с деньгами).
- **Страницы.** Блок «Участие» на странице турнира (форма выбора состава, статусы, реквизиты с кнопкой «Копировать»), «Мои турниры» в кабинете, турниры на странице команды, подтверждённые команды в списке турнира.
- **Тесты.** `npm run smoke` дополнен ≈30 проверками заявок (оплата, лист ожидания, заморозка, отмена, возврат, удаление).
- **Решения, которые стоит подтвердить:** закрытие за 60 минут, срок оплаты 24 часа, лист ожидания на 8 команд, возврат только вручную (значения в `server/src/config.js`).
